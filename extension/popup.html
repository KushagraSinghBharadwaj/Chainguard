How an analysis works

1Input and validation

An address must be 0x plus 40 hex characters. Calldata must be even-length hex. Invalid input is rejected before any request is sent.

2Address type detection

The backend reads the account's bytecode to decide whether it is a wallet or a contract, then runs the matching analysis.

3Data collection

Alchemy, Etherscan, GoPlus and the stored OFAC and ScamSniffer lists are queried. Every check reports completed, partial or skipped.

4Deterministic rules

Rules turn the data into findings. Each has a severity, confidence, source and fetch time.

5Risk level

LOW, MODERATE, HIGH, CRITICAL or INSUFFICIENT DATA. Only the rules engine sets it. LOW is not a guarantee of safety.

6Limitations and sources

Every report lists what could not be checked and which sources contributed, with timestamps.
